# Инструкция пользователя

## 1. Запуск приложения

Откройте терминал в папке проекта и выполните:

```powershell
docker compose up --build
```

После запуска откройте приложение в браузере:

```text
http://localhost:5173
```

Для остановки приложения используйте:

```powershell
docker compose down
```

Если нужно полностью очистить базу данных и создать ее заново из SQL-скрипта:

```powershell
docker compose down -v
docker compose up --build
```

## 2. Вход в систему

Для проверки доступны учетные записи:

| Роль | Почта | Пароль |
| --- | --- | --- |
| Администратор | admin@warehouse.local | Admin123! |
| Сотрудник | employee@warehouse.local | Warehouse123! |

Администратор может просматривать складские данные и создавать пользователей.
Сотрудник может работать с приходами, расходами, справочниками и отчетами.

## 3. Главный экран

После входа открывается рабочий стол склада. На нем отображаются основные показатели:

- сумма приходов;
- доступные остатки;
- последние приходы;
- последние расходы;
- быстрые действия для перехода к основным разделам.

Если данные не загрузились, проверьте, что все контейнеры запущены:

```powershell
docker compose ps
```

## 4. Приход на склад

Раздел "Приход" используется для оформления поступления материалов.

Порядок работы:

1. Откройте раздел "Приход".
2. Заполните номер ордера и дату.
3. Выберите поставщика.
4. Выберите тип документа и укажите номер документа.
5. Выберите материал и единицу измерения.
6. Укажите количество и цену за единицу.
7. Нажмите кнопку добавления прихода.

После успешного добавления запись появится в журнале приходов, а остатки по материалу увеличатся.

Важно:

- номер ордера должен быть уникальным;
- количество должно быть больше нуля;
- цена должна быть больше нуля;
- счет материала должен соответствовать выбранному материалу.

## 5. Расход со склада

Раздел "Расход" используется для оформления выдачи материалов со склада.

Порядок работы:

1. Откройте раздел "Расход".
2. Укажите номер расхода и дату.
3. Заполните направление или получателя.
4. Выберите материал и единицу измерения.
5. Укажите количество.
6. Укажите номер расходного документа.
7. При необходимости добавьте комментарий.
8. Нажмите кнопку оформления расхода.

После успешного оформления запись появится в журнале расходов, а остатки по материалу уменьшатся.

Важно:

- номер расхода должен быть уникальным;
- количество должно быть больше нуля;
- нельзя списать больше, чем есть на складе;
- направление отгрузки и номер документа должны быть заполнены.

## 6. Справочники

В разделе "Справочники" можно просматривать основные данные склада:

- материалы;
- поставщиков;
- единицы измерения;
- реквизиты поставщиков;
- счета материалов.

В таблице материалов доступен поиск по названию, коду, классу, группе и счету.

## 7. Отчеты

В разделе "Отчеты" доступны аналитические операции:

- просмотр поставщиков, которые поставляли выбранный материал;
- подсчет количества поставщиков по банковскому адресу;
- просмотр сумм поставок по материалу.

Для отчета по материалу выберите нужный материал из списка.

Для отчета по банковскому адресу заполните:

- индекс банка;
- город;
- улицу;
- дом.

Затем нажмите кнопку подсчета.

## 8. Администрирование

Раздел "Администрирование" доступен только пользователю с ролью администратора.

В этом разделе можно:

- просматривать список пользователей;
- создавать новых сотрудников;
- создавать новых администраторов.

Для создания пользователя заполните имя, почту, пароль и роль, затем нажмите кнопку создания.

## 9. Регистрация сотрудника

На экране входа можно переключиться в режим регистрации.

Для регистрации нужен код приглашения:

```text
INVITE-2026
```

или

```text
WAREHOUSE-ACCESS
```

Новый пользователь, созданный через регистрацию, получает роль сотрудника.

## 10. Типичные проблемы

Если приложение не открывается:

```powershell
docker compose ps
```

Проверьте, что контейнеры `client`, `api` и `db` находятся в состоянии `Up`.

Если данные не загружаются после перезапуска API, выйдите из аккаунта и войдите снова.
Токены авторизации хранятся в браузере и становятся недействительными после пересоздания API-контейнера.

Если нужно посмотреть ошибки сервера:

```powershell
docker compose logs api
```

Если нужно посмотреть ошибки клиента:

```powershell
docker compose logs client
```

Если нужно посмотреть состояние базы данных:

```powershell
docker compose logs db
```
